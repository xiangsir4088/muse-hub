# 虚拟文物 3D 展厅 — 设计规格

日期：2026-09-22
状态：已与用户逐节确认

## 1. 项目目标

构建轻量级、跨终端的虚拟文物展示空间，解决物理展陈空间不足与馆藏文物利用率的矛盾，降低异地观众观展门槛。核心不是全景图轮播，而是具备自由漫游交互能力的沉浸式数字孪生场景。

三大功能支柱：

1. **三维空间交互**：WebGL 自由行走、环顾，平滑无卡顿；展柜与展墙建模精度可识别展陈逻辑（展线流向、展区划分）。
2. **高精度文物还原**：5~8 件重点文物支持点击进入"鉴赏模式"——无极缩放、任意旋转，可观察口沿、底部款识、纹饰阴刻线等微观细节（纹理标准 4K）。
3. **智能导览系统**：≥2 条主题路线（"青铜礼制脉络""宋代雅趣生活"），一键自动漫游，按行进位置触发语音讲解，中英双语字幕，全程零操作。

内容管理后台：运营人员可上传 3D 模型、替换讲解音频、调整展品摆放位置、按主题组合临展/特展，无需开发介入。

## 2. 资产现状与假设

- 无文物扫描模型（用户确认选项 C）：软件侧使用开源/程序化文物模型做演示验证（优先公有领域来源：Smithsonian 3D 数字化藏品、Met Open Access、Poly Pizza 等 CC 授权模型，不足处以程序化生成器补充）；模型接口按标准 glTF/GLB 设计，日后扫描成品可直接替换，不改架构。
- 无讲解音频：预留标准音频槽位（每件文物 × 中英两个 mp3），占位音频由离线 TTS 脚本生成（如 `edge-tts`/`espeak-ng` 批量转 mp3，中文 xiaoxiao/英文 aria 等公共声音），正式录制后覆盖同名文件。
- 部署：先在本地 Windows 直接运行（一条 `npm run dev`），后续发布到 GitHub。
- 运营规模：单人/少数策展人员，单账号口令鉴权，无角色权限体系。

## 3. 总体架构

**方案**：Three.js 自研引擎（Vite + React + TypeScript）+ 轻量 Express 后端。已否决：纯静态无后台方案（违背运营自助上传）、Babylon.js + Headless CMS（依赖外部数据库，本地部署繁琐）。

```
博物馆3D展厅/
├── package.json          # 根脚本：npm run dev 一条命令全起
├── web/                  # Vite + React + TS 前端
│   └── src/
│       ├── viewer/       # 3D 展厅（漫游/环顾/碰撞/LOD/画质分级）
│       ├── appraise/     # 鉴赏模式（无极缩放、细节热点）
│       ├── tour/         # 智能导览（路径动画、音频触发、双语字幕）
│       └── admin/        # 管理后台（同仓库路由 /admin）
├── server/               # Express 管理 API
│   ├── api/              # 上传、内容读写、登录
│   └── auth.js           # 单账号口令 → HMAC token
└── content/              # ★ 数据即文件，全部进 Git
    ├── scenes/           # 展厅布局 JSON（展墙、展柜、灯光、展品位置）
    ├── routes/           # 导览路线 JSON
    ├── exhibits/         # 文物元数据 JSON
    ├── models/           # .glb（DRACO 压缩）
    ├── audio/            # zh/en 讲解 mp3
    └── textures/         # 4K 贴图（KTX2 压缩）
```

**关键决策**：

- **无数据库**：`content/` 目录是唯一数据源；JSON 写入采用"临时文件 + 原子重命名"防损坏；Git 历史即内容版本历史。
- 开发：`npm run dev` 并发启动 Vite（5173，代理 `/api` 与 `/content`）+ Express（3001）。生产：`npm run build` 后 Express 托管 `dist/` 静态产物与 `content/`，单进程。
- 鉴权：浏览完全公开；写接口需登录 token（内存 session）。
- GitHub 发布路径：浏览端可导出纯静态版上 GitHub Pages；带后台需任何可运行 Node 的主机。

## 4. 展厅场景与漫游交互

### 4.1 场景描述

展厅由参数化模板生成（面积、展墙分段、展区划分）。展柜三类：独立柜、沿墙柜、展台。展品实例字段：

```json
{ "id": "…", "exhibitRef": "exhibits/…json", "position": [x, y, z],
  "rotation": [x, y, z, w], "hallZone": "bronze-hall", "case": "case-03" }
```

展线流向不硬编码在几何中，由导览路线节点顺序体现（与第 6 节共用节点数据）。

### 4.2 漫游操作

- PC：鼠标拖拽环顾（阻尼平滑）+ WASD 行走。点击地面寻路移动本期不做（见第 10 节）。
- 移动端：单指环顾 + 虚拟摇杆行走；双指缩放不用于漫游（留给鉴赏模式）。
- 碰撞：玩家圆柱体 vs 展柜 AABB 盒，沿墙滑动不卡步。

### 4.3 性能分级

自动检测设备能力 + 手动档位切换：

| 档位 | DPR 上限 | 阴影 | 纹理 | 模型 |
|------|---------|------|------|------|
| 高   | 2.0     | 开   | 4K   | 全精度 |
| 中   | 1.5     | 关   | 2K   | LOD1 |
| 低   | 1.0     | 关   | KTX2 1K | LOD2 |

### 4.4 加载策略

首屏仅当前展厅：引擎代码约 200KB gzip + 程序化展厅几何（几 KB JSON）；展品模型按需异步加载，先显示 LOD2 占位再换高精度。GLB 走 DRACO/Meshopt 压缩。

## 5. 鉴赏模式

- **进入**：漫游中点击展品（或靠近后浮现"鉴赏"按钮）→ 相机 0.8s 缓动至特写轨道视角，背景压暗虚化，切换独立交互层。
- **无极缩放**：滚轮/双指捏合，从器物全貌缩至贴面 5~10cm 微观视距；接近阈值自动切换 4K 全分辨率贴图 + 各向异性过滤拉满。
- **任意旋转**：拖拽环绕（含俯视底部、平视口沿），惯性阻尼；"翻转到底部"快捷姿势按钮专看底款。
- **细节热点**：元数据标注 N 个热点 `{position, normal, title{zh,en}, body{zh,en}}`，屏幕显示圆点，点击相机飞至特写并弹说明卡。
- **补光**：方向光 + 环境光"补光条"，用户可调光位，使浅浮雕与刻线在侧光下显出层次。
- **退出**：Esc/返回 → 相机回到漫游位置；若导览处于暂停，从当前节点续播。

## 6. 智能导览

### 6.1 路线数据结构（`content/routes/*.json`）

```json
{
  "id": "bronze-ritual",
  "title": { "zh": "青铜礼制脉络", "en": "Bronze Ritual Traditions" },
  "nodes": [
    {
      "exhibitId": "ding-001",
      "walkTo": [0, 0],
      "lookAt": [0, 0],
      "triggerRadius": 2.5,
      "audio": { "zh": "ding-001-zh.mp3", "en": "ding-001-en.mp3" },
      "subtitle": { "zh": "…", "en": "…" }
    }
  ]
}
```

### 6.2 行为

- **自动漫游**：相邻节点间 Catmull-Rom 样条生成行走路径；位置与视线分别独立插值（先到位、再缓转头对准展品）。全程零操作。
- **触发**：实时检测与节点距离，进入 `triggerRadius` 播放对应语言音频 + 滚动字幕；播完停留 2s 再前往下一节点（设置项可改为"不等播完"）。
- **双语**：语言全局切换（中/英）；字幕三态：仅中、仅英、中英对照。
- **控制**：首页选路线 → 开始/暂停/上一站/下一站/退出；任何手动输入自动暂停导览并提示"继续跟随？"。
- **首批内置路线**："青铜礼制脉络"（5~6 件青铜器）、"宋代雅趣生活"（瓷器/香具等），展品从开源模型池中分配。

## 7. 内容管理后台（`/admin`）

四个功能区，全部操作映射为对 `content/` 内 JSON 与文件的读写：

1. **文物管理**：上传 `.glb`（自动校验，可选 gltf-transform 压缩）、中/英音频、4K 贴图；元数据表单（名称/年代/材质/中英简介）；鉴赏热点在 3D 预览弹窗中点选模型表面生成坐标，无需手填 xyz；保存生成 `exhibits/*.json`。
2. **展厅布局**：3D 编辑模式——从展品库拖拽入场景，gizmo 移动/旋转/缩放，磁吸对齐展柜与地面；增删展柜、调整展区；保存覆盖 `scenes/*.json`，自动保留最近 10 份快照可回滚。
3. **导览路线编辑器**："边逛边录"——点"记录节点"存当前相机站位/朝向/最近展品；节点拖拽排序、改触发半径、绑音频与字幕；内置"预览试走"验证触发时机。
4. **展览管理**：新建临展/特展 = 勾选展品组合 + 选/克隆展厅布局 → 独立场景 JSON，与常设展并存；展览可设上下线，首页多入口卡片。

**API**（写接口均需 token；读走 Express static）：

- `POST /api/admin/login`
- `POST /api/upload`（模型/音频/贴图）
- `GET /api/content/:kind` · `GET/PUT /api/content/:kind/:id`

## 8. 错误处理与安全

- 模型/音频加载失败：该展品位显示占位底座 + 错误角标，不阻塞其余展厅内容。
- JSON 校验失败：后台拒绝保存并给出行级错误提示。校验用 Zod schema，前后端共用同一份定义。
- 上传防护：文件类型白名单 + 大小上限（模型 200MB / 音频 20MB）+ 服务端重命名存储，防路径穿越。

## 9. 测试策略

- **单测（Vitest）**：场景/路线 schema 校验、样条插值与触发判定纯函数、原子写文件。
- **冒烟（Playwright）**：桌面 + 移动视口各一遍——加载展厅、环顾、点击进鉴赏、跟随导览走过一个触发点、后台登录并保存一次展品位置。
- **性能门槛（脚本）**：低档首屏网络传输 < 3MB；中档漫游平均 FPS > 30。

## 10. 明确不做（YAGNI）

- 多人账号/角色权限、评论社交、展厅外的电商/预约等衍生功能。
- 点击地面寻路自动移动（WASD/摇杆已满足漫游需求）。
- 真实文物扫描管线（属内容制作外包范畴，本系统只定义接入标准）。
- VR/WebXR 头显模式（架构不阻碍，日后另立需求）。
- 全球 CDN/对象存储部署（当前本地文件 + Git 即够，发布时再评估）。
